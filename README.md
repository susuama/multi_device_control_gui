# multi_device_control_gui

複数の実験機器を制御し、測定データの表示・記録を行うためのWindows向けGUIアプリケーション。将来の機材追加や画面追加に対応しやすいよう、機器通信・測定管理・画面表示の役割を分けている。

**現在作成途中です。**
以下の方針で実装を進めています。

- 新しい機材を追加しやすくするため機器固有の通信・制御処理はドライバークラスに実装し、`DeviceManager` でまとめて管理します。機材の追加時はドライバーを追加・登録し、必要に応じてデータ型やAPIを拡張します。
- 作者とCodexで実装を分担するため、バックエンドとフロントエンドのAPI通信部分は作者、UI部分はCodexが担当します。フロントエンドではAPI通信とUIの処理を分け、担当範囲を明確にします。
- 用途や機材に合わせて画面を構成できるよう、グラフやテーブルなどの個々の機能を「ビュー」という最小単位で実装します。ビューを表示する共通の枠を「パネル」とし、表示するビューとパネルの数・配置を組み合わせて対応します。同じ機器を複数のパネルで扱えるよう、接続状態と測定データは画面間で共有する方針です。

## 現在の実装

- バックエンド：ダミーパワーメーターの探索・接続・切断、測定管理、CSV記録用のサービスを実装。実機用ドライバーは未実装。
- 通常画面：A2を基準にしたワークスペース。1パネル・左右2パネル・上下2パネルを切り替え、各パネルにログまたは既存のAPIテストを表示する。
- デザインデモ：複数パネル、グラフ、テーブル、画像、設定画面の見本。データ・画像は見本データで、実機通信やファイル保存は行わない。
- 測定・記録の画面への接続、記録用APIの登録、WebSocketによるデータ配信、ウィンドウ間の同期は今後実装する。

実機はPyLabLibの `UC480Camera` と `PM160` を想定。これらを使ったデータ取得・実験は別の自作ソフトで行えている。本プロジェクトへの組み込みはこれから進める。

## 既知の制約

- 機器設定の取得・更新APIは未実装で、501を返す。
- 実機を使った取得・記録は、本プロジェクトでは未確認。
- 終了処理でエラーが起きた場合、残りの機器の切断・後処理が実行されないことがある。処理待ちの時間制限も今後見直す。
- CSV記録は、保存内容・同名ファイルの扱い・書き込み失敗時の動作を含む検証が不足している。実験で使用する前に追加検証が必要。

## 導入・起動

通常画面はログ1パネルで開く。各パネル左上の切り替えから「APIテスト」を選んで送信すると、共通クライアントが送信先・HTTPステータス・所要時間・通信失敗を記録する。ログビューは直近1,000件をウィンドウ内で共有し、ビューを閉じても収集を続ける。ログのクリアは同じウィンドウの全ログビューへ反映される。

バックエンドの端末ログ、別ウィンドウとのログ同期、ログのファイル保存は未実装。フロント側からは`frontend/src/logging/logStore.ts`の`logger.info(source, message)`、`warn()`、`error()`で記録できる。パネルとワークスペースはログ収集やAPI通信を担当しない。

フロントエンドの確認は`frontend`で`npm run build`、`npm run lint`、`npm test`を実行する。テストはNode.js 24の標準テストランナーで確認しており、追加のテスト用ライブラリは使用しない。

実機用SDK・ドライバーの関係で、対応OSはWindowsに限定する。

- [導入・起動方法](doc/起動方法.md)：Python・フロントエンドの導入、通常画面とデザインデモの起動、テストの実行。
- [ThorCamをPythonで操作する](doc/ThorCam.md)：カメラ用SDKとPyLabLibの導入、UC480Cameraなどの操作例。
- [OPMをPythonで操作する](doc/OPM.md)：パワーメーター用ドライバー、NI-VISA、PM160の操作例。

実機用の資料は別の自作ソフトで使用している機器の導入メモ。本プロジェクトのダミー動作・デモ確認には、実機用SDKやPyLabLibの導入は不要です。
