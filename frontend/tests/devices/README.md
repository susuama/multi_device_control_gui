# デバイス管理・個別デバイスのUI検証

製品のApp・Workspace・2つの機器ビューを、実バックエンドとダミーパワーメーター2台・ダミーカメラ1台へ接続する。Edgeと、検証専用の表示したWebView2ウィンドウで同じ操作を確認する。検証専用ビューは製品画面へ追加しない。

リポジトリのルートから実行する。

```powershell
.\.venv\Scripts\python.exe -B frontend/tests/workspace/run.py --suite devices --output "$env:TEMP/device-ui-verification"
```

既存の仮想環境、`frontend/node_modules`、Microsoft Edge、WebView2、FFmpegを使う。`tests/pywebview/run_real.py`の実バックエンド検証サーバーと、ワークスペースのUI検証ランチャーを再利用する。ビルド、HTTP・WebSocketのポート、Edge・WebView2のプロファイル、動画の保存先を通常起動から分ける。実機は使用しない。

`result.json`の`ok`とbrowser・webview両方の`runs[].ok`がtrueなら成功。失敗時は`error`・`stack`と各ログを確認する。動画とメタデータは出力先の`browser/recordings`・`webview/recordings`に残す。

片方だけを実行する場合は`--surface browser`または`--surface webview`を付ける。この場合の`ok`は指定した1環境の結果であり、両方での成功とは区別する。設定送信の時刻・内容・最大並行件数と、保存済みメタデータの履歴件数も結果JSONに残す。

確認する内容：

- 通常画面の探索・機器一覧・機器情報・接続・切断。探索連打で要求を重複送信しない。
- 通常の説明・成功メッセージを表示せず、周期取得中も機器一覧の位置が変化しない。
- パワーメーターの各設定項目の適用、空欄の拒否、適用済み値の共有。
- 2パネルと機器切り替えで未適用入力を保持し、周期GETで上書きしない。
- 他パネルが変更した未編集項目を最新値のまま送信し、「元に戻す」で最新の確定値へ戻す。
- カメラの露光時間のms・秒変換、ゲイン・ゲインブースト・FPSの適用。
- 露光時間・ゲインの即時反映と、それ以外のボタン適用を区別する。空欄を送信しない。
- 150ms間隔の連続操作と最終値反映。700msの低速応答中に編集を続け、2パネルの露光・ゲインを最新値へ集約する。同一機器への最大並行送信は1件、未適用のFPSは即時反映へ混ぜない。
- 先行要求の応答で新しい入力や、確認済み値へ戻した最終操作を消さない。
- 非表示・対象変更で待機分を取り消し、再表示で自動再送しない。入力だけを復元し、明示的な再適用で送る。
- 実動画の記録中のFPSロックとゲイン変更、開始時設定の保持。検証ではFFV1形式を明示的に選ぶ。製品の既定形式を決めるものではない。
- HTTP失敗・結果不明でも入力を残し、変更要求を自動再送しない。
- ライト配色と狭いパネルで、本文・操作欄・フッターを表示する。

設定適用失敗と不正JSON応答は、検証サーバーだけに存在する経路から一度だけ注入する。製品API・ドライバーは変更しない。実機での設定反映や撮影画像の変化は、この検証の対象外。

Nodeの`settingsUpdates.test.mjs`では送信の直列化・集約・取消し・失敗停止と、機器間の独立性を確認する。実機の応答時間や長時間記録の負荷を保証する検証ではない。

同じ検証画面で通常の「測定・記録」ビューも操作する。機器ごとの取得と最終受信、開始時の対象固定、後発機器の除外、記録停止後の取得継続、全取得停止後の記録継続、複数パネルの条件入力保持、記録名衝突、遅い停止、最終JSON失敗の明示再試行、動画初期化の部分失敗を確認する。保存されたCSV・動画・フレーム時刻CSV・最終JSONの読戻しは別途行い、画面の停止要求だけで保存成功とはしない。最終JSONの再試行成功後も過去のerrorが残るバックエンド契約を維持する。

テーブル・グラフは実ダミー受信の表の日時・経過秒・パワー値とChart.js描画を確認し、記録が継続することを検査する。取得停止後に検証用数値1,050件を共有ストアへ投入する別条件で、投入分の全件保持とテーブルの直近1,000件表示、追従OFF、列・機器・パネルごとの設定保持、グラフの全範囲データ・Canvas描画・最小高さからの再拡大を検査する。表示操作で変更HTTPやWebSocketが追加されないことも比較する。検証用投入データを実機取得の証拠として扱わない。

イメージビューは実ダミーカメラのJPEGを2パネルでデコードし、ライブ更新・fit表示・200%の実表示幅・スクロール・独立した倍率保持を確認する。Object URLの生成・解放を計測し、表示中は最大2件、両ビューの非表示で0件になることを確認する。取得停止後のJPEGを検証用に復元する別条件で、通信断での最後の画像保持、最小高さからの復元、不正JPEGのエラーと正常JPEGへの復帰、測定ID切替時の解放も確認する。画像表示で追加の変更HTTP・受信接続を作らないことと、実記録の継続を確認する。これはURL管理の確認であり、プロセス全体のメモリリークや実機性能の保証ではない。

以前の640×480画像を使う試行では、FFV1保存の`-slices 1`固定が原因で失敗した。2026-11-06の修正では保存ROIの幅352以下かつ高さ288以下は1スライスを維持し、それを超える場合は自動選択（`-slices 0`）にした。UIの検証もFFV1で実動画を保存する条件に戻した。
