# 共通UI・ワークスペースの検証

実機・製品バックエンドを使わず、既存の模擬APIと、製品のWorkspace・Panel・ログ・APIテスト・共通UI部品を接続する。検証用ビューはこの画面にだけ登録する。

リポジトリのルートから実行する。

```powershell
.\.venv\Scripts\python.exe -B frontend/tests/workspace/run.py --output "$env:TEMP/workspace-verification"
```

既存のPython仮想環境、`frontend/node_modules`、Microsoft Edge、WebView2を使用する。製品と同じreact-mosaic-componentを使用する。ビルド・ポート・EdgeとWebView2のプロファイルは通常起動から分ける。実行環境にはローカルHTTP・WebSocket通信とネイティブGUIの利用権限が必要。

Edgeはヘッドレス、WebView2は検証専用ウィンドウを一時的に表示して実行し、結果を返したら閉じる。今回の環境では非表示のWebView2でResizeObserverのサイズ変更通知が止まったため、最小高さ・再拡大の検査には表示したウィンドウを使う。`result.json`の`ok`と両方の`runs[].ok`がtrueなら成功。失敗時は各runの`error`・`stack`と`browser.log`・`webview.log`を確認する。ビルドと専用プロファイルは出力先に残す。

`--surface browser` / `--surface webview`で片方だけを実行できる。その場合の`ok`は指定した環境だけの結果になる。

確認する内容は次のとおり。

- ログの表示件数・末尾追従、APIの入力途中の機器ID・JSON・購読条件、折りたたみ状態をビュー切り替え後に復元する。
- 2枚目のパネルを隠して再表示しても入力を残し、別パネルの入力を混ぜない。
- 機器別の未適用入力・表示範囲・倍率を持つ検証用ビューで、パネルごとの状態を復元する。
- 非表示ビューのEffectを解除し、再表示時に再購読する。全ビューを隠しても共通の受信と模擬記録は継続し、変更要求を追加送信しない。
- `OperationButton`が接続状態の変更に追従し、無効な理由は常設の文字ではなく`aria-description`とツールチップで渡す。
- 通信異常で最後の値と最終受信時刻を残し、全体の「状態を再取得」から復旧できる。
- 最終確認時刻・再取得ボタンはウィンドウ共通フッターへ一度だけ表示し、周期取得に追従する。通常状態・更新中・操作案内の説明文は表示せず、エラー・結果不明の詳細は上部に残す。240〜640px幅で、ダーク・ライトとも22pxのフッター内に収まることを確認する。
- HTML5ドラッグによる中央での入れ替えと辺への再配置、配置切り替え後の配置・DOM・入力保持を確認する。
- パネルヘッダーから右へ分割し、新ID・同じ現在ビューで元の領域を等分する。元の入力と周囲の領域を維持し、新規パネルへ未適用入力を複製しない。
- 最大化と再押下で元の配置・比率・DOM・入力を復元する。最大化中の分割・閉じる・配置切替と、全パネルを閉じた後の初期配置復元を行い、取得・記録の変更要求を送信しないことを確認する。
- 境界をマウスでドラッグし、最小高さで本文を隠してヘッダーを残し、再拡大時に入力を復元する。長い本文、狭い幅、ライト配色も確認する。

この検証は模擬APIに対するUIの確認であり、実ファイルの保存、実機の取得、製品用のグラフ・画像・ROIビューの確認は含まない。

同じランチャーの`--suite devices`は、製品の機器ビューを実バックエンドとダミー機器へ接続する別の検証。内容と保存先は[機器UI検証](../devices/README.md)を参照。
